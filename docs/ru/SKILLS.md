# Скиллы Pokeball

Установите официальные скиллы Pokeball, чтобы дать ИИ-агенту практические инструкции для работы в вашем проекте. Каждый скилл содержит конкретные шаги реализации или ревью и проверки для своей задачи. Можно установить только нужные рабочие процедуры.

Скиллы — производные инструкции. Приоритет сохраняет [упорядоченный набор Core](../../spec/pokeball-architecture-core.md). Установка не предоставляет среду исполнения и не доказывает соответствие приложения Pokeball.

**[Установка одним промптом](agents/INSTALL.md#install-skills-with-your-agent).** Откройте проект приложения и вставьте готовый промпт в его ИИ-агента. Агент установит все пять скиллов в текущий проект, сохранит существующие файлы и сообщит точный коммит источника. Чтобы установить меньше скиллов, измените список. Ниже также приведены ручные шаги для установки в проект или личную область.

<a id="choose-a-workflow"></a>

## Выберите задачу

| Скилл | Для чего нужен |
|---|---|
| [`pokeball`](../../skills/pokeball/SKILL.md) | Создание и изменение Ball, его собственного State, чистых решений, входных данных и обычных тестов. Начните с него для повседневной работы над функциональностью. |
| [`pokeball-async`](../../skills/pokeball-async/SKILL.md) | Работа, продолжающаяся после завершения вызова, связь результатов с запросами, повторы, отмена, неизвестные исходы и статус операций. |
| [`pokeball-composition`](../../skills/pokeball-composition/SKILL.md) | Границы между владельцами полномочий, зависимости, чтение, Application Surface, Assembly и владение Flow. |
| [`pokeball-binding`](../../skills/pokeball-binding/SKILL.md) | Создание и изменение общих механизмов записи, принятия, отправки, выполнения, долговечности, безопасности и ограничения работы. |
| [`pokeball-review`](../../skills/pokeball-review/SKILL.md) | Ревью указанной реализации или изменения: поиск регрессий во владении состоянием, принятии, границах, асинхронном поведении и тестах. |

В каждом скилле один краткий `SKILL.md` с полными рабочими инструкциями, а также `LICENSE` и `NOTICE.md`. Уведомления — юридические материалы, а не контекст задачи. Любой скилл можно установить отдельно: для его применения не нужны локальная копия Pokeball, соседние скиллы, предварительное чтение документации или доступ к сети.

<a id="download-once"></a>

## Скачайте один раз

Скачайте с [GitHub](https://github.com/4wl2d/Pokeball/tree/master/skills) полный каталог каждого выбранного скилла, включая `SKILL.md` и уведомления. Подойдёт установщик скиллов из GitHub, который сохраняет каталог целиком; [промпт установки через агента](agents/INSTALL.md#install-skills-with-your-agent) задаёт каталог проекта и проверки сохранности файлов.

Для ручной установки один раз клонируйте репозиторий в новый промежуточный каталог, затем скопируйте только нужные скиллы. В этих командах для POSIX-оболочки указан пример расположения; перед запуском выберите ещё не существующий каталог:

```sh
pokeball_source="$HOME/Downloads/pokeball-skills-source"
mkdir -p "$(dirname "$pokeball_source")"
git clone --branch master --single-branch \
  https://github.com/4wl2d/Pokeball.git "$pokeball_source"
git -C "$pokeball_source" rev-parse HEAD
```

Если в выбранном месте уже есть файлы, изучите их и выберите другое расположение, не заменяя существующее. Запишите показанный SHA коммита в заметки об установке: он определяет точный скачанный снимок GitHub. Официальная публикуемая ветка — [`master`](https://github.com/4wl2d/Pokeball/tree/master).

Промежуточная копия репозитория нужна только как источник скачанных файлов. Установленные копии продолжат работать после её перемещения или удаления. Копируйте весь каталог скилла, а не один `SKILL.md`.

<a id="make-selected-skills-discoverable"></a>

## Сделайте выбранные скиллы доступными агенту

Выберите одну область установки и задайте `pokeball_skills` в той же оболочке. Для установки в проект запускайте команды из корня принимающего проекта.

| Агент и область | Каталог назначения |
|---|---|
| Codex, все ваши проекты | `pokeball_skills="$HOME/.agents/skills"` |
| Codex, текущий проект | `pokeball_skills="$PWD/.agents/skills"` |
| Claude Code, все ваши проекты | `pokeball_skills="$HOME/.claude/skills"` |
| Claude Code, текущий проект | `pokeball_skills="$PWD/.claude/skills"` |

Эти локальные каталоги обнаружения описаны в документации [Codex](https://developers.openai.com/codex/skills) и [Claude Code](https://code.claude.com/docs/en/skills#where-skills-live). Другие среды с поддержкой Agent Skills могут использовать иные каталоги; сверяйтесь с документацией выбранной среды. [Формат Agent Skills](https://agentskills.io/specification) не задаёт универсальное место установки. В английском источнике документация проверена 2026-09-05.

Пример устанавливает только `pokeball`. Чтобы добавить другие процедуры, допишите их имена из таблицы в строку `for`. Команды отказываются использовать существующий путь назначения, включая неработающую символическую ссылку, и создают обычные каталоги.

```sh
: "${pokeball_source:?Сначала задайте путь к промежуточной копии репозитория}"
: "${pokeball_skills:?Сначала выберите каталог назначения из таблицы}"
mkdir -p "$pokeball_skills"
for pokeball_skill in pokeball; do
  pokeball_target="$pokeball_skills/$pokeball_skill"
  if [ -e "$pokeball_target" ] || [ -L "$pokeball_target" ]; then
    printf 'Путь уже существует; изучите его перед изменением: %s\n' "$pokeball_target" >&2
    break
  fi
  if [ ! -f "$pokeball_source/skills/$pokeball_skill/SKILL.md" ]; then
    printf 'Исходный скилл не найден: %s\n' "$pokeball_skill" >&2
    break
  fi
  cp -R "$pokeball_source/skills/$pokeball_skill" "$pokeball_target"
done
```

При установке в проект команда может хранить установленные каталоги в системе контроля версий вместе с приложением: тогда все рабочие копии получат одинаковые файлы скиллов. При личной установке каждый разработчик выбирает свой набор. Сохраняйте приложенные уведомления вместе с файлами.

Проверьте список скиллов в агенте и откройте выбранный скилл, чтобы убедиться, что его инструкции доступны. Если список не обновился, начните новую сессию. В Codex скилл явно вызывается через `$skill-name`, в Claude Code — через `/skill-name`. Автоматический выбор зависит от среды и описания скилла.

Команды выше предназначены для POSIX-оболочек. В Windows скопируйте выбранный каталог целиком через файловый менеджер или установщик среды в документированный каталог обнаружения; права на создание символических ссылок не нужны. Выполнение в Windows здесь не проверено.

<a id="use-it-in-your-application"></a>

## Используйте скиллы в приложении

Рабочий каталог агента должен оставаться в вашем приложении. Агент применяет установленные инструкции к исходному коду, принятым контрактам проекта и тестам. Непосредственные доверенные вызовы используют типизированную целевую операцию и область вызова; сама граница Ball не требует токена, носителя причинности или числовой квоты композиции. Для динамической работы, независимой доставки и восстановления сохраняются обязанности по идентичности, ёмкости и обработке сбоев, которые активирует такой путь. [Примеры Counter и Document](COMPOSITION.md) показывают ограниченную локальную форму.

Примеры запросов для Codex:

```text
Используй $pokeball, чтобы добавить предел количества товаров в существующий Ball корзины.
Повторно используй его привязку к среде исполнения и проверь изменённое бизнес-правило.

Используй $pokeball-async, чтобы устаревшие результаты поиска не заменяли более новые.
Перед изменением кода изучи существующие контракты запросов и статусов.

Используй $pokeball-composition, чтобы подключить ещё одного разрешённого потребителя
к этой capability увеличения Counter. Повторно используй последовательную привязку
и проверь возврат, отказ до принятия и сбой исполнителя после принятия.

Используй $pokeball-binding, чтобы реализовать границу принятия этой привязки.
Принятый профиль приложения и требования к гарантиям находятся в ./docs/binding.md.

Используй $pokeball-review для ревью этого diff на регрессии Pokeball.
Покажи конкретные последовательности событий, ведущие к сбою, и затронутые правила реализации.
```

Для Claude Code замените `$pokeball…` на соответствующую команду `/pokeball…`. При ручном использовании файла укажите полный путь к скиллу и ту же задачу.

Если приложение уже использует установленный [Agent Pack](agents/README.md), сохраните принятые Core, политики проекта, привязку к среде исполнения и инструкции. Добавление скиллов не переносит этот контракт на новую версию. Перед изменением поведения, зависящего от контракта, явно разрешите конфликт версий источников; при запросе на обновление самого пакета следуйте [руководству установки Agent Pack](agents/INSTALL.md). Шаблон overlay необязателен и не становится принятой политикой от одного копирования.

<a id="update-when-requested"></a>

## Обновляйте по запросу

Источником распространения служит GitHub. Нет фонового обновления, реестра пакетов или отдельно выпускаемой утилиты Pokeball для командной строки. Изменения источников и рабочих процедур сопровождаются вместе в этом репозитории. Установленные каталоги — снимки; скачивание новой копии репозитория их не меняет.

Скачайте новый снимок в новый промежуточный каталог по инструкции клонирования выше. Если сохранили прежнюю промежуточную копию, сначала проверьте её:

```sh
git -C "$pokeball_source" status --short --branch
git -C "$pokeball_source" remote get-url origin
git -C "$pokeball_source" rev-parse HEAD
```

Для нужной официальной промежуточной копии на `master`, в которой нет локальных изменений или коммитов для сохранения, запишите прежний SHA и выполните обновление:

```sh
git -C "$pokeball_source" pull --ff-only origin master
git -C "$pokeball_source" rev-parse HEAD
```

[`--ff-only`](https://git-scm.com/docs/git-pull) отказывается обновлять разошедшуюся историю. Если копия изменена, находится на другой ветке или её история разошлась с удалённой, сначала изучите различия и решите, как их сохранить. Не выполняйте сброс, очистку, перезапись или принудительное обновление как часть установки.

Заменяйте выбранные установленные скиллы целыми каталогами:

1. Запишите новый SHA источника и точный список заменяемых скиллов. Сравните каждый текущий каталог с записанным исходным снимком и изучите локальные доработки.
2. Скопируйте каждый новый скилл целиком во временное место вне каталогов обнаружения агента. Проверьте наличие `SKILL.md`, `LICENSE` и `NOTICE.md`.
3. Выберите уникальное расположение резервной копии вне области обнаружения и убедитесь, что его ещё нет. Явно решите, какие доработки перенести в новую копию; сохраните оригиналы в резервной.
4. Между сессиями агента переместите старый каталог в резервное место, затем поставьте подготовленный новый каталог по прежнему пути. Если замена не удалась, восстановите резервную копию до использования скилла. Заменяйте каталог целиком: копирование поверх старого может оставить устаревшие файлы.
5. Запишите новый SHA и повторно внесённые локальные изменения. Начните новую сессию и убедитесь, что установленные инструкции доступны.

Если раньше скилл устанавливался символической ссылкой, сначала сохраните доработанные исходные файлы как обычные резервные копии. Замените саму ссылку полным скопированным каталогом скилла; не записывайте через неё и не меняйте общий источник. Полученная установка не зависит от той копии репозитория.

Обновление закреплённого контракта Pokeball в приложении требует отдельного явного решения. Обновление скилла для написания кода не меняет этот контракт.

Сопровождение можно отдельно поручить агенту:

```text
Обнови только <выбранные имена скиллов>, установленные в <абсолютный каталог скиллов>,
из https://github.com/4wl2d/Pokeball, ветка master. Подготовь один точный снимок Git,
изучи локальные доработки и сохрани резервную копию каждой существующей установки
вне области обнаружения скиллов перед заменой её полного каталога. Сохрани доработанные
файлы и сообщи коммиты источников и повторно внесённые локальные изменения.
Сохрани принятый контракт Pokeball моего приложения без изменений.
```

Инструкции по установке и сопровождению находятся на этой странице. Сами скиллы содержат только рабочие процедуры реализации и ревью кода на основе Pokeball. Для изменения этих процедур используйте [руководство по созданию скиллов](SKILL-AUTHORING.md).
