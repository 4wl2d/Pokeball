## 7. State и полномочия

<a id="71-state-kinds"></a>

### 7.1. Виды состояния

<!-- pkb-translation:pba-source:start id="PBA-14" title="Explicit State Kind" -->
**Исходное положение PBA-14 — Явный вид State.**

- **Правило:**
  - Виды состояния в этом подразделе различаются по полномочиям и смыслу; они не взаимозаменяемы.
  - `EphemeralState` содержит только механику UI/транспорта, которая не может изменить бизнес-Decision.
  - Значение UI/транспорта, влияющее на решение, — это зафиксированный State или явный доверенный текущий вход `Pulse`/`DecisionContext`, но никогда не скрытый источник полномочий в эфемерном состоянии.

  | Вид | Владелец | Смысл |
  |---|---|---|
  | `SovereignState` | Nucleus конкретного Ball | Канонические изменяемые смысловые факты |
  | `EphemeralState` | Interaction/транспорт | Механика UI и транспорта, которая не может изменить бизнес-Decision |
  | `ReplicaState` | Resource/адаптер чтения | Кеш или копия внешнего источника с данными о происхождении |
  | `CapturedInput` | Владелец Flow/операции | Неизменяемый версионированный снимок для решения и восстановления |
  | `ReadModelState` | Read Model Ball | Производное состояние для запросов |
  | `Projection` | Никто | Неизменяемый выход, не источник полномочий |
  | `RuntimeState` | Runtime | Почтовый ящик, захваты, попытки, автоматический выключатель, трассировка |
- **Применимость:** `A`: каждое значение, похожее на состояние, включая значения UI/транспорта, которые могут повлиять на Decision.
- **Владелец объявления:** владелец State/протокола; Interaction владеет только механикой, не влияющей на решения.
- **Область действия:** точная область, заданная полями «Правило» и «Применимость».
- **Владелец контроля / доказательств:** сопоставление типов и состояния, а также тесты текущего входа/сохранения значений UI, влияющих на решения.
- **Разрешение, сбой и соответствие:** разрешается по §0.2; нарушение означает несоответствие в указанной области, если Правило не задаёт более строгий локальный сбой.
- **Повторное использование и поведение без условия применения:** используйте общий словарь; механика, не влияющая на решения, может быть эфемерной; для отсутствующих видов состояния строка не нужна.
- **Основной путь проверки:** `§17.1`
<!-- pkb-translation:pba-source:end -->
<a id="72-one-mutable-factone-authority"></a>

### 7.2. Один изменяемый факт — один владелец полномочий

<!-- pkb-translation:pba-source:start id="PBA-11" title="Single Semantic Authority" -->
**Исходное положение PBA-11 — Единый владелец смысловых полномочий.**

- **Правило:**
  > **В одной пересекающейся смысловой области не может быть двух независимых писателей, каждый из которых считает своё значение каноническим.**

  Область может включать:

  ```text
  semanticId
  namespace / tenant / realm
  stateKey or key range
  region or jurisdiction
  validity interval
  ```

  Внешний провайдер или база данных может быть авторитетным первоисточником. Тогда локальный `Ball` владеет состоянием решения, состоянием операции или репликой, но не присваивает себе владение внешним каноническим фактом.
- **Применимость:** `A`: каждый изменяемый смысловой факт.
- **Владелец объявления:** карта владения проекта и Ball-владелец.
- **Область действия:** точная область, заданная полями «Правило» и «Применимость».
- **Владелец контроля / доказательств:** границы доступа / тесты владения.
- **Разрешение, сбой и соответствие:** разрешается по §0.2; нарушение означает несоответствие в указанной области, если Правило не задаёт более строгий локальный сбой.
- **Повторное использование и поведение без условия применения:** можно сослаться на один State Belt; не копируйте описание владения.
- **Основной путь проверки:** `§17.5`
<!-- pkb-translation:pba-source:end -->
### 7.3. State Belt

<!-- pkb-translation:term:start name="State Belt" -->
**State Belt** — логическая карта изолированных владельцев состояния; это не API общего изменяемого хранилища.
<!-- pkb-translation:term:end -->

```text
StateBelt {
    AuthBall owns auth.session
    CatalogBall owns catalog.searchSession
    CartBall owns cart.contents
    CheckoutFlow owns checkout.operation
}
```

State Belt НЕ ЯВЛЯЕТСЯ обязательным общим хранилищем, singleton API или объектом, доступным каждому модулю. Это архитектурная модель владения и, при необходимости, сгенерированный реестр.

<a id="74-prohibition-on-direct-cross-cell-reads"></a>

### 7.4. Запрет прямого чтения между ячейками

<!-- pkb-translation:pba-source:start id="PBA-13" title="State Isolation" -->
**Исходное положение PBA-13 — Изоляция State.**

- **Правило:**
  `Nucleus` одного Ball НЕ ДОЛЖЕН читать изменяемое состояние другого Ball через ссылку в памяти, селектор общего хранилища или общую ORM-сессию.

  Допустимые способы получить данные другого Ball:

  - публичный контракт чтения;
  - версионированный неизменяемый снимок;
  - принадлежащий получателю `ModuleResult`, переданный проверенным `ModuleResultPulse`;
  - наблюдаемый сигнал/событие;
  - Read Model;
  - проверка/резервирование на стороне получателя.

  Слой представления может объединять несколько проекций для показа, если это объединение не принимает бизнес-решений между областями полномочий и без отдельного механизма не заявляется как согласованный снимок.
- **Применимость:** `A`: каждый граф Ball.
- **Владелец объявления:** Ball и Assembly.
- **Область действия:** точная область, заданная полями «Правило» и «Применимость».
- **Владелец контроля / доказательств:** границы импортов/хранилищ.
- **Разрешение, сбой и соответствие:** разрешается по §0.2; нарушение означает несоответствие в указанной области, если Правило не задаёт более строгий локальный сбой.
- **Повторное использование и поведение без условия применения:** общая проверка графа; без флага `noCrossStateReads`.
- **Основной путь проверки:** `§17.5`
<!-- pkb-translation:pba-source:end -->
<a id="75-captured-input"></a>

### 7.5. Сохранённый вход

Flow или долгая операция может сохранять только нужные поля из чужого состояния или снимка на определённый момент. Ниже приведён каталог условий применения, а не обязательная форма обёртки:

```text
CapturedInput {
    sourceCorrelation?
    sourceProtocolOrSchemaVersion?
    verifiedProvenance?
    capturedAt?
    purpose?
    fields
    expiresAtOrDeletionTrigger?
}
```

То же правило действует для значения из более раннего `Pulse` или `DecisionContext`, которое нужно следующему Decision: оно становится ограниченным типизированным значением в зафиксированном State либо явно вводится заново через новый доверенный вход. Корреляция добавляется, если можно перепутать несколько источников/операций; явная версия — если независимый протокол/схема может измениться или значение переживает развёртывание/восстановление; происхождение — при пересечении границы доверия/полномочий; поле хранения/удаления — если срок жизни отличается от состояния, содержащего значение. Простое значение с локальным владельцем в одной сборке можно хранить прямо, без этих метаданных. История inbox, outbox, runtime или участников никогда не заменяет данные, доступные для чтения при принятии решения. Сохранённый вход не становится вторым изменяемым источником полномочий. Перед строгим действием получатель может потребовать ожидаемую версию, резервирование или повторную проверку текущего состояния.

<a id="76-single-writer"></a>

### 7.6. Единственный писатель

<!-- pkb-translation:pba-source:start id="PBA-12" title="Single Writer" -->
**Исходное положение PBA-12 — Единственный писатель.**

- **Правило:**
  В каждый момент у одного `BallInstance` есть один логический писатель. Профиль Inline обеспечивает это дисциплиной вызовов; конкурентный профиль — циклом с единственным писателем; долговечный профиль с переносимым владельцем — эпохой владения или барьером, которые обеспечивает хранилище.

  Аренды или локального мьютекса процесса недостаточно, если два runtime могут независимо считать себя владельцами и писать в одно авторитетное хранилище.
- **Применимость:** `A`: последовательное принятие; `R`: владелец может перемещаться.
- **Владелец объявления:** привязка исполнения/состояния к среде.
- **Область действия:** точная область, заданная полями «Правило» и «Применимость».
- **Владелец контроля / доказательств:** цикл вызовов или барьер в хранилище и тесты конкурентности.
- **Разрешение, сбой и соответствие:** разрешается по §0.2; нарушение означает несоответствие в указанной области, если Правило не задаёт более строгий локальный сбой.
- **Повторное использование и поведение без условия применения:** контракт привязки можно повторно применять в точной области хранилища; при фиксированном владельце барьер не нужен.
- **Основной путь проверки:** `§17.6`
<!-- pkb-translation:pba-source:end -->
<a id="77-commutative-updates-under-single-writer-acceptance"></a>

### 7.7. Коммутативные обновления при принятии единственным писателем

Ball может объявить коммутативный или подобный CRDT контракт слияния для конкурентного входа или независимо подготовленных значений обновления с доказанными свойствами:

```text
associative
commutative
idempotent or duplicate-aware
deterministic conflict handling
bounded metadata
```

Такой контракт меняет семантику конфликтов и слияния, но не отменяет принятие единственным писателем: один логический писатель упорядочивает слияния и назначает `CommitRevision`. Два независимых писателя, одновременно принимающих изменение одного `BallInstance`, выходят за рамки Core, даже если алгебраические свойства соблюдены. Настоящий профиль с несколькими писателями требует отдельной спецификации; без неё всегда действуют §7.6 и PBA-12.

<a id="definition-source-records-for-7"></a>

### Исходные записи определений для §7

Эти помеченные определения — единственные исходные данные глоссария для терминов, которыми владеет этот раздел.

<!-- pkb-translation:term:start name="Captured Input" -->
**Captured Input** — неизменяемое ограниченное значение с минимальным набором полей из прежнего входа/результата/контекста/снимка авторитетного источника, сохранённое для более позднего решения/восстановления. Корреляция источника, версия, происхождение и метаданные удаления добавляются, только если этого требует реальное условие источника, развёртывания, доверия, неоднозначности или срока жизни; значение не становится вторым изменяемым источником полномочий.
<!-- pkb-translation:term:end -->


<!-- pkb-translation:term:start name="EphemeralState" -->
**EphemeralState** — механика Interaction/транспорта: фокус, прокрутка, анимация, состояние парсера или сокета, которая не может изменить бизнес-Decision. Значение UI/транспорта, влияющее на решение, — это зафиксированный State или явный доверенный текущий `Pulse`/`DecisionContext`, а не эфемерный источник полномочий.
<!-- pkb-translation:term:end -->

<!-- pkb-translation:term:start name="Field-Minimized" -->
**Field-Minimized** — содержит ровно те смысловые поля и поля корреляции, версии, происхождения, действительности и срока жизни, которые нужны по реальным условиям решения и границ значения; поля без условий применения опускаются, а не заполняются значениями по умолчанию или заглушками.
<!-- pkb-translation:term:end -->

<!-- pkb-translation:term:start name="Replica State" -->
**Replica State** — внешняя/кешированная копия с происхождением, ревизией и свежестью; она не обладает полномочиями для принятия решений.
<!-- pkb-translation:term:end -->

<!-- pkb-translation:term:start name="Sovereign State" -->
**Sovereign State** — каноническое изменяемое состояние с единственным владельцем полномочий для принятия решений.
<!-- pkb-translation:term:end -->


<!-- pkb-translation:term:start name="StateKey" -->
**StateKey** — идентификатор локальной границы состояния/согласованности/раздела BallInstance.
<!-- pkb-translation:term:end -->
