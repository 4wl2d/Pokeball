## 4. Наборы тестов профилей

Запускайте только наборы, выбранные действующим профилем или заявлением о гарантиях.

### Inline / Transient

- канонический `decide(...) -> SnapshotDecisionResult<State>` и плоский `AcceptedSnapshotDecisionFrame<State> { commitRevision?, nextState, outputs }`, ошибки публикации принятия и полный сохранённый кадр внутри процесса при наличии выходов; ветвь Event не требуется;
- растущая синхронная работа проверяет выбранный предел ёмкости или причинности на N/N+1 со связью доверенных Pulse/Context каждого элемента и допуском только в среде исполнения; полное конечное локальное исполнение не требует полей причинного бюджета;
- успех локальной команды, отказ цели до принятия и ошибка исполнителя после принятия сохраняют состояние владельца и порядок завершения источника без обязательных типов токена, носителя или слота уровня; завершение, выдающее новую работу, отменяет доказательство замкнутой конечной цепочки;
- отсутствие скрытых затрат очереди/потока/сериализации;
- явная граница потери процесса, когда возможна внешняя неопределённость; и
- бенчмарк — только при заявлении о производительности.

### BoundedConcurrent

- заполнение mailbox/обратное давление и конечные воркеры; справедливость — только когда раздельные очереди входов могут голодать;
- вход/результат вне порядка плюс дубликаты — только когда возможна повторная доставка;
- гонки отмены/крайнего срока/результата — только при достижимости путей; и
- конечные причинные бюджеты/бюджеты разветвления — только для присутствующих причинных или маршрутизируемых измерений, с точным счётом выхода источника/маршрута/потребителя и сохранением причинных области/глубины/бюджета при асинхронной передаче; точные `N/N+1` не принимают частичный Decision.

### SnapshotOutbox / EventJournal

- выбранный кадр своего режима: плоский `AcceptedSnapshotDecisionFrame<State>` для SnapshotOutbox либо `AcceptedEventCommit { ..., decision: EventDecision }` для EventJournal, с восстановлением State через `evolve` без независимого Event `nextState`; сбои до/внутри/после транзакции; неизвестная фиксация — только при возможной неопределённости;
- восстановление из принятых записей без повторного запуска текущего кода перехода;
- повторная доставка, потеря ACK, исчерпание попыток, статус, хранение и ограждение — только когда достижимы; и
- сохранность принятого результата цели при сбое до отправки, `DispatchStopped` цели с ключом кортежа и Pending/Unknown источника до проверенного результата/сверки; и
- точные значения, сохраняемые между Decision, и миграции — только когда последующая работа их использует.

### Hardened / Isolated

- подлинность/целостность контекста актора и доказательства неверного/неодобренного issuer/realm, когда контекст актора может изменить Decision или авторизацию/выбор результата Query/чтения статуса, независимо от привилегий;
- audience/полезная нагрузка/истечение срока/отзыв и текущее доказательство действия — только для соответствующих привилегированных мер;
- минимальные технические полномочия ограниченного класса операций на реальной границе capability, включая отказ замене оболочкой/администраторскими учётными данными;
- применимое поведение параметризованного, структурированного, укоренённого в capability или контекстно кодированного безопасного приёмника — только для ребра интерпретатора/диалекта;
- точная политика пути/области для каждого достижимого пути секрета в State, выход, сохранение, сериализацию, журнал и телеметрию; и
- обычные ограниченные учётные данные остаются допустимым доверенным отрицательным сценарием `InProcess + Hardened`, если нет требования сдерживания враждебного кода или отдельного principal; и
- изолированное разделение учётных данных плюс пределы сбоя/выхода из изоляции/ресурсов, когда сдерживание требуется, выбрано или заявлено.
