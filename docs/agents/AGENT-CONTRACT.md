# Pokeball Agent Contract

> **Status:** derived noncanonical package. It neither defines nor extends Pokeball Core. Before using it, pass [BASELINE.md](BASELINE.md). Core prevails over this package.

Every `PKB-AR-*` rule is defined exactly once in this file. `A`, `P`, `R`, and `C` mean `always`, `path-triggered`, `risk-triggered`, and `claim-triggered` under Core §§0.2 and 20.1.

## Workflow

Before changing or reviewing Pokeball scope, the agent:

1. verifies the exact baseline and source precedence;
2. reads the affected authoritative source plus only the accepted policy reference, local delta, Assembly edges, and waiver record that exist;
3. derives applicability from the closed type/protocol/profile/route inventory plus reachable risks and explicit claims;
4. resolves each triggered guardrail to one construction proof, local declaration, or immutable in-scope policy reference plus an allowed delta;
5. runs base tests and only the path/risk tests that are reachable; and
6. creates a full evidence/gate record only for a release, conformance, or other explicit guarantee claim.

Metadata may add a trigger but cannot suppress one inferred from source or risk. In ordinary design, implementation, and adoption work, a proven-absent trigger has no mechanism, empty table, zero placeholder, explanation row, or proof artifact. Ambiguous absence is treated as present until an accepted decision closes it. When a conformance/release claim or an accepted ambiguity-resolution decision relies on absence, `PKB-AR-GOV-005` instead requires the exact static proof owned by Core §0.2.

Core §8.12 is a reference-only runtime concern index. It routes an agent to the sole normative anchors for cause/context, bounds, identity, admission, acceptance, dispatch, accepted-work preservation, observations, faults, recovery, reads, and lifecycle/fencing; it creates no additional component, field, mechanism, or trigger. The Core `Runtime / acceptor` is the mechanical binding role for applicable validation handoff, admission/reservation, publication of the selected mode-specific accepted frame, scheduling of retained outputs, and conversion of verified mechanical observations into declared `ControlPulse` routes. It owns no business schema, policy, permission, result selection, retry/fallback choice, or direct Sovereign-State write outside accepted snapshot/event publication and a later serialized `decide`.

Interaction is the logical adapter role. A Trusted Boundary is the separately inspectable authorized verification-and-construction edge, commonly realized at Interaction or route ingress; it is neither a fourth authority nor a synonym for Interaction, and co-location transfers no business-policy or State authority.

The command bridge in `PKB-AR-PRT-004` preserves these exact target-owned frames and delivery identity:

```text
accepted source ModuleCommandRequest
  -> verified ModuleCommandPulse(commandSource, effectiveProtocolIdentity, command, issuerProvenance)
  -> target decide / accepted target Decision
  -> ModuleResultOutput(semanticHandle = commandSource.semanticHandle,
                        target-frame sourceOrdinal, commandSource, payload)
  -> verified ModuleResultPulse(commandSource, resultSource,
                                effectiveProtocolIdentity, result, issuerProvenance)

result-delivery key = (effectiveProtocolIdentity, commandSource, resultSource)

CommandRejectedBeforeAcceptance {
    commandSource
    effectiveProtocolIdentity
    boundaryResponse:
        ValidationFailure
      | AdmissionFailure
      | DecisionRejected(BusinessRejection)
    targetBoundaryProvenance
}
```

`ModuleResultOutput.semanticHandle` is correlation only. The output always consumes target output-count and canonical `maxOutputBytesPerDecision` bounds and consumes one target delivery/status slot when retained, retried, or observable. Target `DispatchStopped` uses the result-delivery tuple and establishes no source business/status facet. A forged carrier creates no trusted source input. An accepted same-state result advances the snapshot revision, or uses accepted `NoDomainChange` in EventJournal. Within the idempotency horizon, a duplicate before any accepted result exists returns only verified ACK proof of the already accepted target frame and pending-result state; a duplicate after result acceptance redelivers the exact accepted result frame. Neither path runs another Decision, increments revision, or creates another Resource action or semantic output.

The level-1 alternative-completion reservation is established before source acceptance. If target acceptance wins, it consumes level 1 and must reserve the level-2 result completion. If validation, admission, or target `decide` rejects before acceptance, the target consumes no accepted level and the boundary transfers level 1 to the source carrier Decision. Failure to reserve level 1 prevents source acceptance and dispatch; failure to reserve level 2 prevents target acceptance and returns `AdmissionFailure(CausalBudgetExceeded)` through the carrier. A carrier-handling Decision reserves any further synchronous outputs from the remaining budget, and async transport preserves the same causal scope/depth/budget without inventing the same-stack transfer rule.

## Fail-closed conditions

Stop the affected change or claim when an applicable policy reference is missing, mutable, stale, cyclic, conflicting, wrong-version/profile/binding/environment, or overridden outside its allowlist. A policy reference, `WaiverRecord`, or `TriggerAbsenceProof` cannot suppress a present trigger, weaken a law, or convert a `MUST`/`MUST NOT` violation into conformance; a direct-cycle waiver is deliberate non-conformance. Stop on carrier/result conflict, dynamic refusal reclassification, an idempotency conflict represented as Nucleus `DecisionRejected`, duplicate-before-result that waits, re-decides, fabricates a result, or repeats a Resource action, unknown/open-string admission reason, or a stage mapping that rewrites an accepted fact. Stop when a trigger is ambiguous and no accepted decision resolves it. Do not stop merely because an absent path has no document in ordinary work.
