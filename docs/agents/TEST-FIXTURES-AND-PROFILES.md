## 4. Profile suites

Run only suites selected by the effective profile or claim.

### Inline / Transient

- canonical `decide(...) -> SnapshotDecisionResult<State>` and flattened `AcceptedSnapshotDecisionFrame<State> { commitRevision?, nextState, outputs }`, acceptance-publication faults, and complete in-process retained frame when outputs exist; no Event branch is required;
- growing synchronous work exercises its selected capacity/causal bound at N/N+1, with per-item trusted Pulse/Context association and runtime-only admission; complete finite local execution needs no causal-budget fields;
- local command success, target pre-acceptance refusal and executor failure after acceptance preserve owner state and source completion ordering with no mandatory token/carrier/level-slot type; a completion that issues more work invalidates a closed finite-chain proof;
- no hidden queue/thread/serialization tax;
- explicit process-loss boundary when external ambiguity can exist; and
- benchmark only when making a performance claim.

### BoundedConcurrent

- mailbox full/backpressure and finite workers; fairness only when separately queued inputs could starve;
- out-of-order input/result, plus duplicates only when duplicate delivery is possible;
- cancellation/deadline/result races only when those paths are reachable; and
- finite causal/fan-out budgets only for present causal or routed dimensions, with exact source-output/route/consumer counting and async handoff preserving causal scope/depth/budget; exact `N/N+1` accepts no partial Decision.

### SnapshotOutbox / EventJournal

- selected mode-specific frame: flattened `AcceptedSnapshotDecisionFrame<State>` for SnapshotOutbox or `AcceptedEventCommit { ..., decision: EventDecision }` for EventJournal, with State reconstructed through `evolve` and no independent Event `nextState`; before/inside/after-transaction crashes; unknown commit only when ambiguity is possible;
- recovery from accepted records without rerunning current transition code;
- redelivery, ACK loss, attempt exhaustion, status, retention, and fencing only when reachable; and
- accepted target result survival across crash-before-dispatch, target tuple-keyed `DispatchStopped`, and source Pending/Unknown until verified result/reconciliation; and
- exact retained cross-Decision values and migrations only when later work uses them.

### Hardened / Isolated

- actor-context authenticity/integrity and wrong/unapproved issuer/realm evidence whenever actor context can change a Decision or Query/status-read authorization/result selection, independently of privilege;
- audience/payload/expiry/revocation and current action proof only for the corresponding privileged controls;
- minimum technical authority for the bounded operation class at a real capability boundary, including rejection of a wrapper/admin-credential substitute;
- applicable parameterized, structured, capability-rooted, or context-encoded safe-sink behavior only for an interpreter/dialect edge;
- exact-path/scope policy across every reachable State, output, persistence, serialization, log, and telemetry secret path; and
- an ordinary scoped credential remains a valid trusted `InProcess + Hardened` negative fixture when no hostile-containment or separate-principal requirement exists; and
- isolated credential separation plus crash/escape/resource caps when containment is required, selected, or claimed.
