# Working contract for coding tasks

These workflows are derived guidance. Pokeball Core owns architecture semantics; the bundled reference sections are derived excerpts for applying those rules. Precedence is Core, an accepted extension within scope, an accepted project policy within scope, then this guidance. Preserve the project's explicit architectural scope; an incompatible contract needs a concrete decision, not a silent migration.

Work from affected source and tests. Find the owner of the mutable fact, the decision/read, accepted-write site and the actual binding. Resolve exact project policies only where this task depends on them. Reuse unchanged enforcement and evidence only within their covered scope. See [everyday responsibility](../../spec/core/reference/21-adoption.md#217-everyday-development-and-production-responsibility) when separating feature work from binding or claim work.

One authority and logical writer, pure decisions from explicit trusted values, closed used protocols, atomic selected-frame acceptance and dispatch afterward remain fundamental. Logical Interaction, Nucleus and Resource roles can share a file; an unused Resource role needs no adapter. The selected Snapshot or Event mutation form remains distinct from a non-mutating read. These are decision reminders; the linked task sources supply the complete applicable contracts. For a logical-role boundary change, use [§5](../../spec/core/03-model-boundaries-zones.md#5-three-logical-zones).

Only actual path, risk and claim triggers add machinery. Source types, static construction and existing scoped policies can carry evidence without a separate manifest. Omit absent categories, empty overlays and routine absence-proof worksheets. When modal strength matters, use [normative words](../../spec/core/00-status-scope-goals.md#01-normative-words). For an uncertain trigger, policy conflict or deliberate deviation, read [applicability](../../spec/core/00-status-scope-goals.md#02-proportionality-principle) and [waivers](../../spec/core/00-status-scope-goals.md#03-waivers-and-conformance-effect); do not assume the trigger absent.

## Read only the relevant reference

All linked workflows and reference sections are contained in this skill. Open the task's route table, then only the complete sections that affect the implementation decision. Bundled numbered sections use `core/<section>.md` within this reference directory. Follow a section's linked semantic dependency when needed. Do not read the entire reference directory as an initialization step.

The bundled excerpts retain the rule's conditions, ownership, failure behavior and verification context. They support code work without a specification checkout, another installed skill, Python or network access. A project-specific decision or implementation fact still comes from the consuming project.
